## Scope and Scaling Notes

- **Skipped outline bullets:** None in Chapter 4 mention a second SQLite version or newer driver release. Pin-enforcement failure paths ("must be able to fail") are exercised in `RCM-07` via a mutated `sqlite/PIN` in a scratch repo copy and a bogus `SQLITE3_BIN` wrapper.
- **Scaling for 4 cores / 7 GiB RAM (< 10-minute target):**
  - `JRN-05b` fuzzes `internal/journalfile` with 5,000 seeded mutations (bit-flips, truncations, header-field smashes, super-journal footer smashes, random garbage).
  - `RCM-02b` runs 30 asynchronous `SIGKILL` iterations during an 8-step `synchronous=OFF` rollback loop.
  - `SCL-01`..`SCL-05` test the full **1,000-connection** outline bullet by scaling per-connection `cache_size` from `-2000` KiB (~4 MiB RSS/connection under `modernc.org/memory`, which would require ~4 GiB RSS and risk OOM with 0 swap on a 7 GiB machine) down to `-256` KiB (60 cached pages, ~0.6 MiB RSS/connection → ~600 MiB peak RSS) on 102-page WAL databases. `SCL-06` runs Experiment 4.2 itself at 4× its default connection count (`-n 256 -k 16 -cache-size -1024 -rows 320`, ~500 MiB peak RSS).
- **Portability:** All four Go attack groups are pure Go (no cgo) and cross-compile cleanly with `GOOS=darwin go build ./...`. Linux-only `strace` checks in `rollback-crashes` use `internal/trace.Supported`; `/proc/self/status` and `/proc/self/fd` reads in `cache-limits` and `cache-scale` are guarded by `runtime.GOOS == "linux"`.
- **Note on `CAC-05`:** The three pre-existing groups (`journal-parser`, `rollback-crashes`, `cache-limits`) were left unmodified in this pass per brief instructions. `CAC-05` constructs a ~1,550-byte database path that exceeds SQLite's unix VFS `MAX_PATHNAME` (512 bytes, `os_unix.c:180`), causing `cache-limits` to exit 1 before printing `CAC-05`; `run-all.sh` records per-group exit codes so `cache-scale` still runs to completion.
