# Chapter 2 Adversarial Tests (`ch02-file-format-and-pages`)

Author: Gemini 4 Neon.  
Run all groups from the repository root:

```bash
bash agent_work/ch02/adversarial/run-all.sh
```

Output is written to `agent_work/ch02/adversarial/results.txt`. All scratch files are isolated under `_work/adv-ch02/` (and large sparse files are deleted immediately after verification).

## Scope and Scaling Notes

- **Skipped outline bullets:** None in Chapter 2 mention a second SQLite version / newer driver release (that bullet was in Chapter 1). Pin-enforcement failure paths are exercised in `HDR-09` and `HDR-10` using a scratch repo copy and a `SQLITE3_BIN` wrapper under `_work/adv-ch02/`.
- **Iteration scaling:** `COR-06` is scaled to 10,000 deterministic seeded mutation iterations (bit-flips, multi-byte overwrites, truncations, and 32-bit integer smashes) on a compact 512-byte-page auto-vacuum database, and `CAP-05` caps race attempts at 40, keeping the entire suite well under the 10-minute target (typically < 1 minute on 4 cores / 7 GiB).
- **Portability:** All four Go attack groups are pure Go (no cgo, no Linux-only syscalls), so `GOOS=darwin go build ./...` compiles cleanly without build tags.

### Group 3: `corrupt-fuzz` (`agent_work/ch02/adversarial/corrupt-fuzz/main.go`)

| ID | Claim attacked | Method | What a BROKEN result would mean |
| --- | --- | --- | --- |
| `COR-01` | 2.2 safety claim: corrupted page/DB headers must never panic (OUTLINE 2.2). | Exhaustively mutate every byte of the 100-byte DB header + page 1 B-tree header + 6 page-role headers with 4 bit patterns each, running all `dbfile` read paths under `recover()`. | A single-byte header corruption triggered a panic (OOB slice, nil deref, divide by zero). |
| `COR-02` | 2.2 bullet: "one flipped byte in a page header (the inspector must report an error, not panic)" compared against SQLite `integrity_check`. | Corrupt page-2 header byte 7 (`fragmented=200`), zero a real `FirstFreeblock`, and lower `CellContentStart` by 20; compare `dbfile` vs `PRAGMA integrity_check`. | `BROKEN` delineates the exact page-header fields `dbfile` does not validate (fragmentation/free-space accounting) where SQLite `integrity_check` reports corruption while `dbfile` silently accepts. |
| `COR-03a` | `dbfile` overflow-chain validation on first/interior pointer corruptions. | Corrupt overflow pointers to `0`, `1`, `999`, self-loop, early termination, and cross-row page sharing; exercise all `dbfile` read paths. | `dbfile` accepted or panicked on a broken overflow chain. |
| `COR-03b` | `dbfile` overflow-chain validation on the LAST overflow page's next pointer vs SQLite `integrity_check`. | Set the last overflow page's 4-byte next pointer to `self` and to `999999`; compare `dbfile` vs `PRAGMA integrity_check`. | `BROKEN` exposes that `dbfile/payload.go` never checks `Next == 0` on the last overflow page, silently accepting corruption that SQLite `integrity_check` catches. |
| `COR-04` | `dbfile` structural validation of freelist, B-tree child pointers, pointer-map collisions, cross-tree page types, cycles, and depth > `MaxTreeDepth` (20). | Inject 14 targeted structural corruptions including a synthetic 23-level B-tree chain and auto-vacuum pointer-map collisions. | `dbfile` accepted a structurally corrupt tree/freelist or panicked / looped infinitely. |
| `COR-05a` | `dbfile` anti-OOM protection and record-decoder edge cases. | Craft a `0x7fffffff` (2 GiB) payload varint on a 2-page file; test reserved serial types `10`/`11`, huge serial types, IEEE NaN->NULL, and odd-length UTF-16. | `dbfile` OOMs, panics, or misdecodes edge-case records. |
| `COR-05b` | `dbfile` detection of overlapping cell pointers vs SQLite `integrity_check`. | Point cell pointer 1 to the same byte offset as cell pointer 0 on a 2-cell leaf page; compare `dbfile` vs `PRAGMA integrity_check`. | `BROKEN` documents that `dbfile` does not check cell-span overlap (build-notes line 214), silently reading duplicate rows where SQLite reports corruption. |
| `COR-06` | `dbfile` crash-safety under sustained random corruption (10,000 mutations). | Run 10,000 seeded mutations (header bit-flips, 1..8-byte random overwrites, truncations, 32-bit integer smashes) on a multi-feature auto-vacuum DB under `recover()`. | Any mutated input caused a panic in `internal/dbfile`. |

### Group 4: `manifest-capture` (`agent_work/ch02/adversarial/manifest-capture/main.go`)

| ID | Claim attacked | Method | What a BROKEN result would mean |
| --- | --- | --- | --- |
| `CAP-01` | 2.3 bullet 1: drop, duplicate, reorder, or corrupt a page in a capture and confirm the verifier refuses, names the page, and writes no output (OUTLINE 2.3). | Run 13 tamper cases across first/middle/last pages (drop, dup, adjacent/distant swap, reverse, rotate, bitflip) with a pre-existing sentinel `outPath`. | `capture.Rebuild` accepted a tampered capture, failed to name the bad page, clobbered `outPath`, or left `.rebuild-tmp`. |
| `CAP-02a` | 2.3 capture integrity when the last page is dropped consistently from BOTH `manifest.txt` (`pages N-1`) and `pages.bin`. | Truncate both `manifest.txt` (updating `pages`) and `pages.bin` by 1 page and call `capture.Rebuild`. | `BROKEN` shows `Rebuild` does not cross-check page 1's SQLite header (`page_count`) against the manifest, so a truncated capture rebuilds into a malformed database. |
| `CAP-02b` | 2.3 manifest role integrity during `capture.Rebuild`. | Rewrite page 1's role in `manifest.txt` to `'bogus-role'` and `'overflow'` while leaving `pages.bin` and sha256 intact; call `capture.Rebuild`. | `BROKEN` shows `ParseManifest`/`Rebuild` neither validates roles against `dbfile.ParseRole` nor verifies roles against the page bytes. |
| `CAP-02c` | 2.3 `capture.Rebuild` handling of an empty 0-page manifest (`pages 0` + 0-byte `pages.bin`). | Feed a syntactically valid 0-page manifest + empty `pages.bin` to `capture.Rebuild`. | `BROKEN` shows `Rebuild` accepts a 0-page manifest and writes an empty 0-byte file that `dbfile.Open` rejects. |
| `CAP-03` | 2.3 bullet 2: refuse databases not at rest (`-wal`, hot `-journal`) and refuse `Rebuild` when side files exist next to `outPath` (OUTLINE 2.3). | Test uncheckpointed `-wal`, passive-checkpointed `-wal`, hot `-journal` in `DELETE`/`TRUNCATE`/`PERSIST`, and stale `-wal`/`-journal`/`-shm` next to `outPath`. | `capture.Pages` or `capture.Rebuild` failed to refuse one of the 8 non-at-rest conditions. |
| `CAP-04` | 2.3 bullet 2: "capture a database that is not closed (a `-wal` exists) and confirm the tool refuses rather than producing a stale file." | Hold an open WAL connection with an active uncommitted write tx after `PRAGMA wal_checkpoint(TRUNCATE)` (`-wal`=0 bytes, `-shm`=32768 bytes); call `CheckAtRest` and `capture.Pages`. | `BROKEN` exposes that `CheckAtRest` allows capturing an actively open WAL database (with live `-shm` and write lock) whenever `-wal` happens to be 0 bytes. |
| `CAP-05` | `capture.Pages` failure hygiene when a database changes mid-capture. | Race a concurrent WAL writer against `capture.Pages` on R0 until `"changed during the capture"` fires; check whether `pages.bin`/`manifest.txt` remain in `dir` and whether `Rebuild` accepts them. | `BROKEN` exposes that `capture.Pages` writes `pages.bin` and `manifest.txt` before its post-capture check and fails to clean them up on error, leaving a seemingly valid capture dir behind. |

| `CAP-07` | 2.3 claim: "the ordered list of page images is the complete state of a closed database" tested on a closed `WITHOUT ROWID` database. | Build a closed valid DB with a `WITHOUT ROWID` table (`integrity_check=ok`) and call `capture.Pages`. | `BROKEN` confirms the `WITHOUT ROWID` census bug propagates directly into R1 capture, preventing capture of valid closed databases. |
| `CAP-08` | `internal/equal` E1 image comparison, manifest diffing, and strict `ParseManifest` validation. | Test non-page-multiple lengths, `pageSize <= 0`, role-only diffs, uppercase hex, trailing blank lines, negative page size, extra columns, and count mismatch. | `internal/equal` misreports diffs or accepts malformed manifests. |
