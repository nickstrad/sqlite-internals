Output is written to `agent_work/ch07/adversarial/results.txt`. All scratch files are isolated under `_work/adv-ch07/`.

## Scope and Scaling Notes

- **Skipped outline bullets:** None (no Chapter 7 bullet referenced a second SQLite version or newer driver release).
- **Iteration scaling:** In `COST-03`, 20-run count stability is exercised on 4 representative cells (`delete/NORMAL 20x50`, `delete/FULL 20x50`, `wal/FULL 20x50`, and full `wal/NORMAL 1000x1` including automatic checkpoint + WAL restart, 80 strace runs total across 4 workers) rather than all 12 cells × 20 runs (240 strace runs, which would repeat the slowest 1000×1 rollback cells 40×). `COST-01` still recomputes all 12 full cells through the pinned C CLI under strace. Total suite runtime is ~2.5 minutes on 4 cores / 7 GiB (well within the 10-minute budget).
- **SeaweedFS prerequisite:** `SNAP-09` tests live S3 vs HTTP parity against SeaweedFS (`compose.yaml`, `COURSE_S3_ENDPOINT` defaulting to `http://127.0.0.1:18333`). Start it with `docker compose up -d seaweedfs`.
- **Cross-platform:** All four Go attack programs compile and vet cleanly on `linux/amd64`, `darwin/arm64`, and `darwin/amd64` with no cgo. `vfs-syscall-map` and `io-cost-falsify` require Linux `strace` at runtime (`trace.Supported`); `govfs-adversarial` and `snapshot-rangefs` run natively without `strace`.
